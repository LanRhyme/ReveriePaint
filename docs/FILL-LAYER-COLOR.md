# 旧填色录制回放兼容修复

PR #52 本轮以主线 `1fce2a44`（1.4.2）为基线重新复现、收窄并验证。以下均为本轮记录，不沿用先前基线的手机验收结果。

## 当前范围

主线 `c59c1cc` 已提供独立 `setFillLayerColor` 接口。图层详情换色和携带 ARGB 参数的 `L_FILL_LAYER` 事件均使用该接口；本次保留其整体替换颜色、不受画笔不透明度和选区影响的行为。

仍在使用的旧路径为：项目回放 → `PlaybackEngine.dispatchLayerOpLocked` → 无颜色参数的 `L_FILL_LAYER` → JNI `fillLayer` → `ReverieCore::fillLayer`。旧事件使用录制上下文里的前景色、不透明度和选区。

`fillLayerForeground` 在当前主线已没有界面调用方。因此撤掉原 PR 对它增加的 `captureContext`，Kotlin、JNI 签名和录制格式均与主线一致。没有修改新换色接口、图层详情界面或新事件分发。

修复只保留：

- 旧填色使用 `fillSelection` 写入像素，替代未配置填充样式或笔刷的 `paintRect` 空操作
- 不透明度只在 painter 上应用一次，避免颜色 alpha 和 painter opacity 重复相乘
- 按目标设备色彩空间构造颜色，继续保留选区、透明度锁定、可编辑性检查和撤销事务

旧文件如果漏记了换色后的上下文，缺失的颜色、不透明度无法从事件流推断恢复；本次不宣称解决这种信息缺失。
