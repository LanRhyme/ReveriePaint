# 湿墨预览/笔迹预测实验记录 (已回滚)

日期: 2026-08-25
结论: **功能整体回滚, 不再继续**。完整实现保存在 backup/wet-ink-v2 分支。

## 实验过程

1. v1 简化折线预览: 未渲染采样以实心折线叠画, 真墨到达替换。
   真机反馈: 图像笔尖(铅笔颗粒等)替换跳变明显、低不透明度偏深后变浅、
   软硬边突变。
2. 门控收紧(按笔尖类型排除图像/管道尖): 误杀 roundmarker 引擎的
   b)_Basic-1 (其设置类非 KisBrushBasedPaintOpSettings), 最常用笔失去
   预览后裸管线的 8ms 攒批步进感("一段一段")暴露。
3. v2 真湿墨层: 图层设备脏区直接导出为覆盖位图(真实 dab 像素, 全笔刷
   正确), MotionPredictor 预测点画笔尖短 streak。真机反馈仍有问题,
   且预测 streak 在抬笔后冻结残留(无输入事件驱动重绘所致)。

## 关键发现 (对后续优化有价值)

- 用户感知的"跟手"主要由即时预览贡献; 预览缺席时裸渲染管线
  (flush 攒批 + 投影合并 + 位图翻转 + Compose 上帧 ≈ 35-60ms) 的
  步进感会被直接感知为"一段一段"。
- Android 公开预测 API 为 android.view.MotionPredictor (API 31+,
  构造需 Context, predict 收纳秒时间戳), 无 PointerPredictor。
- View 触摸层叠加物在抬笔后会冻结: 无输入事件即无 onDraw,
  任何抬笔后才应消失的覆盖内容必须主动补延迟重绘。
- 若重启此方向, 建议起点: v2 分支的引擎侧脏区导出方案
  (renderWetOverlay), 并先解决"覆盖层与正式渲染合成的清除时序"
  与"抬笔冻结"两类问题再做用户验收。
