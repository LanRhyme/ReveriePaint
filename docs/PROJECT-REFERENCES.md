# 本地作品参考图与缓存管理（#78 / #80）

## 本轮收窄方案

作者在 #80 指出参考图是画布外的辅助工具，随 `.revp` 打包会增加文件体积、保存开销、内存峰值和格式维护成本；提交者也反馈实测有卡顿。本轮撤掉资源 ZIP、二进制状态编码、原生资源访问以及保存/导出等待参考图的逻辑，采用作者后续接受的本地作品关联，并按建议增加设置页缓存清理。

当前已同步主线 `5cc4bead`（1.4.5），原本地关联实现基于 `7a37ac16`。本轮仅改 Kotlin、Compose、资源与文档，没有修改 C++、JNI 签名、原生库、工程格式或录制事件。#70 的补修不混入本分支。

## 存储及生命周期

- 私有目录 `files/project_references/<UUID>/` 保存参考图副本；`reference_projects` 偏好用本机作品绝对路径关联 UUID。图片顺序及显示状态存在独立偏好中，不写入工程。
- 导入在 IO 线程流式读取源文件并有界解码。未降采样的 PNG、JPEG、WebP 直接保留源文件编码；需要降采样或其他格式仍转存 PNG。已选图片复用已有本地文件和位图。成功写完全部新增文件后才发布有序列表，失败保留原选择。绘画保存、自动保存和导出不会再次编码、压缩或打包这些图片。
- 打开作品时先读取参考图列表与显示状态；窗口关闭时不解码，打开后才在后台加载并显示加载提示。恢复任务只发布位图，不再次覆盖用户新改的显隐和变换状态。图片解码后预先调用 `prepareToDraw()`；不增加跨作品常驻位图缓存。
- 新作品从空参考图开始；成功打开后按本地路径恢复。保存成功建立关联，自动保存完成后关联自动保存文件，崩溃抢救成功后同样关联。参考图是当前本机工作状态，不是自动保存历史中的参考图快照。
- 画廊内成功改名或移动时迁移路径关联，删除成功后清理不再被其他本地别名使用的副本。绘画页改名保存时关联转移到新路径，保留的旧工程不再共享可变参考集。
- 复制、导出、重新导入的工程和恢复为副本的工程按新作品处理，不自动继承参考图。应用外改名、移动或跨设备传输不会带走关联，需重新添加；相册源图在导入后删除不会影响已存的本地副本。
- 会话与操作编号阻止旧导入/恢复任务回写到新画布；图片读写和清理通过同一互斥锁串行化。离开未保存作品只释放 UI 引用，不立即删除磁盘副本，以免与尚未完成的自动保存关联竞争。遗留临时副本可通过清理入口删除。
- 窗口显隐、灰度、翻转、页签、折叠、缩放、旋转、平移按作品保存；位置、尺寸、允许旋转仍为设备偏好。工具栏显隐入口补上状态持久化调用。

## 缓存清理

“设置 → 通用 → 参考图缓存”显示本机占用并提供清理按钮。确认框说明：删除所有作品及当前作品的参考图副本、显示状态和旧版全局参考图缓存，后续需重新添加；不删除作品文件、相册原图或窗口布局偏好。

清理先失效并取消待完成的导入/恢复，然后在 IO 线程清理指定私有目录与关联。进行中不能再开始参考图导入，失败报告未完全清除，成功后刷新占用。没有默认的过期自动删除机制。参考窗口内原有“清除图片”仅作用于当前作品。

旧 `ref_images/` 默认保留，由“导入旧版参考图”明确添加到指定作品。只有用户确认全局清理时才删除这份旧缓存，不在打开第一幅作品时擅自迁移。

## 限制与维护注意

最多 50 张，单张源输入和一组本地图片文件总量均不超过 64 MiB，解码位图总预算 64 MiB；按采样尺寸解码，最长边目标约 2048。它保存的是参考副本，不是无损原图归档。与画布共存的峰值内存仍需不同设备复查。保留原始编码不改变既有 BitmapFactory 的方向、色彩或动画帧处理行为；不是新增 EXIF 方向或动图支持。

参考图修改独立持久化，不进入绘画撤销栈，也不需要重新保存画布；离开时会取消尚未完成的导入，未完成操作不保证保留。本地关联不是跨设备同步机制。后续新增文件移动/改名/删除入口时，应同步更新关联；不得把参考图重新塞回工程资源表。

此前草稿产生的实验性内嵌参考资源不自动迁移或批量重写，旧测试文件需保留备份后手动重新添加参考图。本轮不再主动写本功能的资源键；打开初版实验工程时，引擎仍可能保留其中已有的资源，本轮不承担旧实验文件瘦身。

## 添加与切换时的性能修正

真机分段测量复现了不必要的转码：同一张 2048×1536 JPEG，解码约 46～65 ms，而再次压缩 PNG 约 360～450 ms，文件从 2,593,184 字节变为 9,360,436 字节。窗口关闭时重新打开作品仍解码了整张参考图。这是撤掉 `.revp` 内嵌后仍然存在的独立成本。

针对这两条路径，保留无需降采样的原始编码，并将关闭窗口的位图读取延迟到打开时。未删掉图片数量、文件大小和解码内存限制；旧 PNG 副本仍可直接读取，无需迁移。此修正不会使已有 PNG 缓存自动变小，也不保证大型图片导入或工程打开完全没有等待。

2026-10-07，在一加 Ace 3 / Android 14 上完成前后对照。固定 256×256 画布、同一张 2048×1536 合成 JPEG，一次预热、三次采样，以下为中位数：

| 指标 | 修正前 | 修正后 |
| --- | ---: | ---: |
| 导入操作总耗时 | 780.6 ms | 370.2 ms |
| 本地图片文件大小 | 9,360,436 B | 2,593,184 B |
| 关闭窗口时重开作品总耗时 | 615.8 ms | 667.5 ms |
| 关闭窗口时已解码参考图数量 | 1 | 0 |
| 打开参考窗口至就绪 | 253.8 ms | 255.7 ms |

导入总耗时在此样本下降约 53%，源 JPEG 字节被完整保留；隐藏窗口的多余解码已消除，但**整体作品切换没有测得加速，仍有慢帧**。不能据此宣称卡顿全部解决，也不能把差异外推为所有设备的提升。操作总耗时包含测试同步和动画，不等同于纯解码耗时。修正前包基于 `7a37ac16`，修正后同步了 `5cc4bead`，并非严格只变一处代码的性能实验。

Window FrameMetrics 中，导入阶段每轮超过 16.7 ms 的帧数中位数由 14 降至 3，但单轮最大帧耗时的中位数由 65.9 ms 变为 73.2 ms；关闭窗口重开作品阶段仍约 297 ms。打开参考窗口阶段的最大帧耗时中位数也从 48.9 ms 变为 70.0 ms。采样较少且阶段帧数不同，仅保留观测值，不把整进程累计掉帧率当作参考图单一路径的数据。后续整体切换优化需单独定位工程读取、渲染与页面重建，不能仅凭这些数据归因。

## 维护者复查流程

1. 新建 A 添加红图，调缩放、翻转并保存；新建 B 确认无红图，添加蓝图保存。往返打开，确认两份图片和状态独立。
2. 重开 A 后保留原图、追加、删除参考图；不重新保存画布直接退出并重开，确认参考选择保留。关闭窗口后结束进程，重开确认显隐状态。
3. 导出或复制 A 为新文件，再打开副本，应无参考图；原 A 的本地参考图仍存在。检查 `.revp` 不新增 `reverie-reference-*` 资源。
4. 画廊内改名、移动作品后检查关联；删除临时作品后检查其独占副本被清理。自动保存恢复仍可在本机读取已建立的关联。
5. 设置页查看占用，先取消清理，确认图片不变；再次确认清理，检查占用下降、所有作品和当前窗口参考图清空。相册原图、作品文件仍在，重新导入可用。
6. 导入或恢复期间切换作品、清理缓存，确认旧任务不能让已清空参考图重新出现；导入无效图片时保留原选择。
7. 顺带检查原有点击添加、长按取色、横屏、大字体及拒绝相册权限时管理已选参考图的行为。
8. 关闭参考窗口并重开作品，应先恢复画布，打开参考窗口后再加载图片；加载期间关闭窗口、切换作品或清理缓存，不能恢复旧窗口状态或让已清空的图片重新出现。无需降采样的 JPEG/PNG/WebP 应保留源字节，大图仍须限制解码尺寸。

## 方案变更记录

初版采用原生资源接口内嵌图片 ZIP 与状态，目的是跨设备打开即有参考图。实测及作者意见表明这增加了保存/解包负担，也超出辅助工具定位，因此本轮移除该方向，保留按作品使用体验和明确清理入口。先前失败记录及验证仍保存在提交历史和本地证据中，不将旧版通过结果套用到新方案。
