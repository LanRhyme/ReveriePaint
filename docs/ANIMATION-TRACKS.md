# 动画音频与轨道模型结论

基线 v1.8.5 (分支 `fix/srt-independent-cels`)

## 结论：轨道模型回退

曾尝试把"根图层组"当作一条轨道, 让帧格显示组内多图层的合成画面。该方向已回退,
原因是引擎模型不支持"每格独立的图层栈":

- 图层树是整份文档一份, 可见性/顺序/不透明度都是图层级属性, 不随帧变化
- 每个图层只有一条关键帧通道 (`KisRasterKeyframeChannel`), 随时间变化的只有像素
- 图层组不参与逐帧动画 (`ReverieCoreAnimation.cpp:585` 排除 `isGroup`), 不能作为
  某一格专属的容器
- 复制图层复制的是整条通道, 因此每一格都会出现同一份内容; 删除图层也是全局生效

做到真正的"每格独立图层"需要修改 C++ 引擎 (逐帧图层参与标记或格容器节点),
当前机器没有 Qt/Krita 构建环境, 无法重编 `libreverie_core.so`。

保留的备份: 分支 `backup/track-model-2026-11-18` (含当时完整的轨道与音频实现),
需要继续该方向时可以从该分支或原生实现继续。

## 保留的行为

- 时间轴仍按图层显示轨道, 每个图层一行, 与 v1.8.5 行为一致
- 普通轨道末尾新建/复制帧不再补尾部边界键, 一次只增加一格
- 图层面板删除普通图层会真正删除该层; 只有字幕主轨删除保持"清空当前格"
- 字幕与音频资源在换文档时清理, 不再跨工程继承

## 音频

音频资源存于 `.revp`, 位置信息单独写在 `reverie.anim.audio_clips`
(`name<TAB>startFrame<TAB>durationFrames`), 前缀与动画标记一致, 不会被识别为音频。

- 导入时读取时长换算成帧数, 起点为当前帧
- 时间轴上方每条音频一行, 拖动修改起始帧, 松手写入工程
- 长按二次确认移除, 停止播放并清理临时文件
- 播放按各自起始帧启动, 已过位置用 `seekTo` 对齐, 循环跟随原有开关
- 旧工程只有字节没有位置时, 按第 0 帧、4 秒兜底
