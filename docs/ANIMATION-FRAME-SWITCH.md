# 动画切帧修复

## 问题与原因

关联 #50，基于主线 `5313eb05` 排查。新建动画画布后，新增或选择后续帧，
时间轴可以显示新位置，但引擎的 `animationCurrentTime()` 仍返回 0。
落笔实际修改第一帧，后续帧没有收到笔画。

`KisImage` 构造时把自身及动画接口移到 `qApp` 所在线程。
`requestTimeSwitchNonGUI()` 只发出 `sigInternalRequestTimeSwitch`；
从 `reverie-render` 调用时，该信号排队到 Qt 应用线程。
本应用使用 Android Handler 驱动文档操作，没有在该线程运行 Qt 事件循环，
所以切帧任务没有提交到图像调度器。随后检查 `isIdle()` 或调用 `waitForDone()`
都不能执行这个仍在 Qt 队列中的信号。

## 修复与影响范围

在既有 `reverie-render` 串行入口直接调用 `switchCurrentTimeAsync()`，
保留 `recordUndo` 选项，并等待图像调度器完成切换，再返回渲染或开始笔画。
继续使用 Krita 的切帧与投影更新机制，不直接修改帧号或更换文档线程。

共用入口覆盖时间轴跳转、新增帧后的定位、临时翻帧、播放步进、
动画导出及工程加载后的当前帧恢复。JNI 签名、文件格式、UI、
双缓冲及笔画热路径不变；预编译 JNI 库同步重建。

## 真机验收

1. 新建 512 × 512 动画画布，在第一帧画红色圆圈。
2. 添加空白帧，确认不再显示第一帧内容；画蓝色方块。
3. 往返点击两帧，确认图案独立；第二帧撤销／重做不改变第一帧。
4. 跳到后面的空位置落笔，确认就地生成关键帧，已有帧保持不变。
5. 开启洋葱皮并往返切帧，再播放／暂停，确认当前帧与播放头一致。
6. 保存并退出工程，再打开，检查各帧内容和继续绘制。
7. 导出 GIF 或 PNG 序列，确认每帧内容不同，导出结束回到原来的帧。
