## 影响评估

全文检查液化 begin/end、参数设置、录制操作码、回放解码、GLES dab 消费与 CPU 写回调用点。涉及普通绘画图层、蒙版目标、多层批次、GPU 预览/提交、CPU 回退、取消/撤销和录制回放。共享头新增液化专用参数，不改变其他工具签名。

文档仍由 C++ 持有；所有引擎操作仍通过 HandlerThread；沿用 front/back Bitmap；手势没有新增视口 key。静止计时复用 Runnable，并按引擎队列背压跳过过载帧，避免积压后集中变形。

## 根因与实现

| 原问题 | 修复 |
|---|---|
| 作用半径是 size × 2.5，光标半径是 size × 0.5 | 新配置把 size 定义为直径，紧支撑半径为 size × 0.5 |
| 推动自动衰减历史位移，反复拉动会松弛 | 新配置持续组合逆映射，不做隐式弹性衰减 |
| 缺少中心与边缘的硬度控制 | 中心平台半径为 hardness × 0.85R，外缘使用 C1 smoothstep 衰减 |
| 大补点会压缩硬边，影响局部稳定性 | 新配置补点间距不超过 size × 0.04，CPU/GPU 同步细分，取整加入浮点容差 |
| 左右推移缺失 | 文档 Y 向下坐标中左为 (dy, -dx)，右为 (-dy, dx)，模式 ID 5/6 |
| 静止膨胀/旋转没有位移，因此被丢弃 | 径向模式接受零位移；强度编码经过秒数，单次最多 40ms，无积压补偿 |
| 压力最低仍有 55% 强度 | 笔压映射 0..1，落笔读取真实压力，手指固定强度；跳过零强度补点 |
| 大画布为整图 GPU 位移场降精度，小笔刷可能失效 | 新配置的原生稀疏场仅按笔刷选择精度；整图 GPU 预算不能保持同等精度时立即回退 CPU |
| GLES 老设备路径调用 Android 26 的 Half.toHalf | 使用纯 Kotlin IEEE binary16 最近偶数编码；不依赖 Android API |
| 改动算法会改变旧录制 | 原生默认保持旧配置；新手势在 BEGIN 前录制尺寸及 PROFILE(46)，回放重置旧配置后按事件切换 |

新强度上限为 100%。推动增益为强度；径向拖动增益按路程/尺寸计算（膨胀/收缩系数 0.8，旋转系数 1.2）；静止计时系数分别为 1.5/s 与 2/s。硬度在手势开始时冻结，CPU/GPU 使用同一配置。

## 真机验收与边界

当前没有连接 Android 设备。必须在实际设备上验证以下项目后才能宣称达到专业软件的使用效果：

1. 细线、棋盘、半透明彩色边缘，七模式，硬度 0/50/100%，不同笔压，拖动与静止一秒
2. 单层、多层、嵌套组叶层、蒙版、剪贴、混合模式及透明锁；预览与提交/撤销/重做/导出逐项对照
3. 8192 画布 8px 小笔刷，确认稀疏 CPU 回退仍有局部效果；低内存设备确认无 GPU 分配峰值崩溃
4. GPU 强制失败/超预算/回读超时，取消手势，切换页面，连续操作与重新进入回放
5. 至少 30 分钟循环操作，记录输入到显示延迟、P95 帧耗时、RSS/GPU 内存和撤销占用

综合审查文档列出的变换蒙版坐标、直接编辑组选中目标、特殊描边层与蒙版混合的自定义合成，以及高位深采样仍需独立实现/实测。本次没有新增冻结、重建、平滑等超出 CSP 七模式参照的交互，不能声称原始全面验收已全部完成。
