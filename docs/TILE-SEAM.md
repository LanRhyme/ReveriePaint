# 放大后画布上出现一条横贯的"切线"——排查记录

> 来源：用户反馈「放大画布看，有时能看到像是有一条线切了一下」，附截图（QQ 压缩，1920x1200，
> 为 2560x1600 平板的 0.75 倍降采样）。**本文是待确认的假设链，不是结论。**

## 1. 从截图量出来的事实

| 观测方式 | 结果 | 含义 |
|---|---|---|
| 逐行差峰值（画布区，x 140..1800） | 只有 y≈657 一处异常大（30.2，中位数 0.46） | 一条全宽水平接缝，画面里只找到这一条 |
| 同一算法在左侧工具栏 / 顶部按钮区 | 峰值落在它们自己的图标边缘（723/827、22/91），y=657 处无异常 | **不是**截图拼接/长截图，是画布内的渲染 |
| y=657 两侧的空白区 | 都是纯白 255 | 不是遮罩、暗化、棋盘格透底 |
| 找「亮线 / 暗线」（缝上比上下 3 行都亮或都暗的列） | 亮线 0 列、暗线 0 列 | 不是"缺一行"或"多一行"的空白/压暗线 |
| 视口高度 1100px 内只有一条接缝 | 接缝周期 > 1100px → 当前缩放 > 2.1× | 只在高倍放大下才装得下相邻两条 |

## 2. 主嫌：512 瓦片边界处的过滤采样退化成硬采样（`ClampedTileDrawer`）

`ClampedTileDrawer.draw()` 用 `BitmapShader(CLAMP, CLAMP)` 画每个瓦片（目的：消除过滤采样读到
瓦片外导致棋盘格透成网格，见文件头注释）。代价是双线性核越过瓦片边界时拿不到邻瓦片的第一个
像素，只能是本瓦片最后一行的复制：

- 边界内侧最后半个纹素：采样 511/512 → 512 被 CLAMP 成 511 → 输出整行 511（不再插值）
- 边界外侧头半个纹素：采样 511/512 → 511 被 CLAMP 成 512 → 输出整行 512
- 结果：**512 个文档像素正好处由"双线性平滑"退化成"最近邻硬边"**，且内容相对两侧最多偏
  半个源像素

这个误差只有 **1 个源像素宽**：
- 1:1 时它正好是屏幕上一条像素线，肉眼看不出来；
- 放大到 2~4× 后变成 2~4 个屏幕像素宽的**锐利台阶**，而旁边全是插值后的柔和过渡 ——
  视觉上就是"隐约一条线把画面切了一下"。

这条与用户描述的三个特征全部吻合：**要放大才看得见**、**时有时无**（取决于该处有没有笔画跨过
512 边界；空白区看不出来）、**跟着画布平移缩放**（文档空间固定），且不是亮/暗线（实测确实没有），
而是"锐利度突变 + 半像素错位"。

代码位置：
- `ui/painting/canvas/CanvasTouchView.kt`：`directBitmapPaint.isFilterBitmap = vm.magnificationInterpolation`
- `ui/painting/canvas/ClampedTileDrawer.kt`：`matrix.setTranslate(left, top)` + `canvas.drawRect(left, top, left+w, top+h, shaderPaint)`

## 3. 用户 10 秒可做的三点确认

1. **设置 → 放大插值 关**：这条线应立刻消失（走 `rawPaint` 最近邻，但整幅都变硬边）。
   → 确认是「放大插值 + 瓦片边界」组合。
2. **停笔等 1~2 秒不动**：线是否自己消失？不消失 → 排除前缓冲真墨覆盖层（它是临时的）。
3. **两条相邻接缝同屏时的间距 ÷ 当前缩放 = 512**？是 → 锁定瓦片边界。

## 4. 修法（确认后实施，需真机验证）

彻底修要能拿到**邻瓦片的边缘像素**，方案是 1px halo：

1. 瓦片位图改为 `(tw+2) × (th+2)`，四周各留 1px 邻居内容；
2. 绘制时 quad 外扩 1 源像素 + shader 平移 `(-1,-1)`，`BitmapShader` 的 CLAMP 只在 halo 外缘
   生效（那里是 512 边界之外 1px，不在视觉路径上）；
3. 引擎 `renderTileToBuffer` 只需把 `docX/docY` 传 `-1`、`bufW/bufH` 传 `+2`（`tileRect` 与
   docRect 取交已现成）；
4. **命中集要按需膨胀一圈**：某瓦片重写时，只有写到的区域碰到自己边缘、才需要连带重写相邻
   瓦片（因为它的 halo 里存的是邻居的边缘像素，邻居变了它就过期）。不膨胀 = 切线从中间挪到
   旁边；
5. `PublishedTiles` 尺寸校验、后备池 `obtainSpare`、`TileDeltaLedger`、`composeTileSnapshot`、
   `renderLayerThumb` 的取整都要改成"内区"语义。

改动面覆盖 COW 状态机与冷却队列，**没有真机验证不能上**。在确认根因前不动这套机制。

## 5. 已排除的

- 脏区漏块：引擎 `renderTileToBuffer` 对此有专门处理（脏区未覆盖整行时绝不读整行带），
  `DirtyRectList` 超容量是合并而非丢弃，`tilesIntersecting` 用的是开区间。
- 截图拼接：静态 UI 在同一 y 上没有断裂。
- 遮罩/暗化/棋盘格透底：接缝两侧空白区都是纯白。
