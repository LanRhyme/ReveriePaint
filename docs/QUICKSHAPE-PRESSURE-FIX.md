## 为什么这样处理

几何顶点不是笔刷采样点。直线只有两个端点，矩形只有角点，仅改变压感数组长度无法保留边中间的压力变化。
逐点模式现在将源笔迹的弧长节点、目标轮廓的顶点和等距节点合并排序，同时输出坐标与压感。
等距采样最多 4096 段，源输入受现有 8192 点捕获上限限制，避免按超大画布尺寸无限分配。
形状顶点保留下来，避免重采样从拐角两侧直接连线而切掉角点。

闭合形状先把原笔迹起点投影到初始识别轮廓，比较两个方向的采样几何误差，确定绘制方向。
草稿保留初始识别结果；用户后续平移或旋转时，不会拿已经移走的形状与原始坐标重新匹配。
对非刚性变形及形状转换，压感按归一化周长对应，不承诺每个像素或角点都维持原始空间对应关系。

逐点开关仍默认关闭。关闭时保留原来的轮廓及平均压感，仅把平均值移到循环外计算一次。
保留原笔迹的取消路径不经过新重采样；提交继续使用已有笔刷六元组及录制事件，不新增 JNI 或录制格式。
无效输入在取消原生原笔迹前被拒绝，用户仍可以取消编辑保留原笔迹。

预览使用复用的 Paint/Path 生成笔触外轮廓，再画主题色边框，不用不透明底色填满笔触内部。
它仍是几何辅助预览，不能复现笔刷纹理、散射、压力传感器和动态笔尖的最终效果。
本次未重新设计胶囊布局，#79 的常驻按钮与二级入口取舍仍应另行讨论。

### 追加排查：回放覆盖了未修改的间距

测试笔刷为 `b)_Basic-5_Size_default`。仅调整压力大小和压力不透明度时，
`saveBrushParam` 会建立自定义配置，但 `spacingCustomized` 仍为 false。
绘制端加载预设后会保留该预设的原生间距；原回放端却仅根据“有自定义配置”，
无条件把界面显示的 spacing 写入引擎。该数值可能经过 UI 限制，并不等于预设实际使用的间距。
间距改变会影响笔触叠加密度，因此不仅笔宽，笔迹浓淡也可能变化。

真机诊断对照使用同一录制与原生引擎：平均压感直线正常回放差 2234 个像素，
只保留原生间距后差异为 0；跳过全部扩展参数也为 0，而只应用扩展形状参数又恢复为 2234。
圆形取消间距覆盖后仍有数百个不同像素，尚未确认其余差异来源，不能算完全修复。

追加修正让普通落笔和多分支笔画都记录 `spacingCustomized`，回放只在用户确实改过间距时覆盖它。
沿用 `CONTEXT_EXT` 原有的一字节标志：0 为未自定义，1 保留旧版“应用全部形状参数”的含义，
3 表示自定义但保留预设间距。版本 1 没有该字节，读取行为不变；没有预设时仍以记录的参数为准。
事件长度、版本号和后续笔画事件不变，旧读端仍能解析新录制，但会继续把 3 当作已自定义，
因此旧版回放仍存在原来的间距问题。旧录制没有间距修改状态，不能可靠追溯修正，保持原解释。
此方案也不打包笔刷资源，无法保证更换设备或修改预设后完全复现笔刷。

早期追加验证通过了架构检查和 49 项针对性 JVM 测试（含 5 项标志兼容与间距规则测试），
完整构建曾因系统内存不足暂停。恢复后确认 1024 MB 和 1280 MB 堆不足以完成本轮编译，
释放系统内存并使用本地 2048 MB 构建配置后完成验证，未修改项目默认构建配置。

### 追加排查：延迟重载覆盖后续设置

显式修改间距的回归又发现：先修改压感、立即调整间距时，120 ms 延迟重载会继续使用旧的
`BrushParams` 快照，覆盖用户后来设置的间距。UI 与录制记录新值，实际绘制却使用旧值。
`saveBrushParam` 的重载分支现在在渲染线程执行时取当前最新的不可变参数快照；
预设索引检查、延迟机制和线程分工不变，不增加笔画热路径处理。
影响范围包括会触发预设重载的压感、笔尖等设置，与紧随其后的间距、大小等参数调整。

真机 A/B 使用相同测试工具、内置笔刷重置入口及快速调参顺序：
旧包的平均压感直线回放差 2216 个像素，最大颜色通道差值 80；最终修正包差异为 0。
保留旧包失败日志，没有用延长两次调参的间隔来掩盖问题。

### 保留待协作定位：逐点压感回放像素差异

这是尚未修复的问题，不能因差值小而忽略，也不应通过放宽断言将结果改为通过。
请其他维护者协助对照实时提交、完整播放、定位末尾三条路径；采样批次、参数恢复和
原生笔刷执行时序均可作为排查方向，但目前没有证据确认其中哪一项是根因。

自动回归的输入条件如下，供搭建相同对照。人工绘制可覆盖交互，但不保证得到相同像素数：

1. 新建 256×256 文档，每项测试前重置内置 `b)_Basic-5_Size_default` 笔刷。
2. 设置笔刷大小 24，开启压感，压力大小 1、压力不透明度 0、压力流量 1；开启逐点压感。
   不修改间距，等待参数重载完成。每次比较均使用相同的预设文件。
3. 通过实际 CanvasTouchView 输入 101 个模拟笔采样（i 从 0 到 100）：
   - 压力为 `0.15 + 0.85 * (1 - abs(i - 50) / 50)`。
   - 直线坐标为 `(50 + 1.5*i, 160)`。
   - 圆形坐标为 `(128 + 55*cos(t), 145 + 55*sin(t))`，`t = 2*pi*i/100`。
4. 保持落笔至 QuickShape 编辑开启，提交形状；读取实际引擎输出像素，确认撤销恢复空白、
   重做恢复原像素。保存同一段录制，分别完整播放及定位末尾后再读取像素。
5. 比较整幅 ARGB 像素的精确相等性，分别记录不同像素数与最大颜色通道差值。
   不比较屏幕截图，避免缩放、预览描边和显示合成干扰结果。
6. 对照关闭逐点压感的直线、跳过 QuickShape 的自由压感圆，并重复执行排查时序影响。

圆形分别为 `493` 和 `651`。同一圆形录制的完整播放与定位末尾之间有 311 个像素不同，
最大通道差值 2。直线曾在另一独立运行中完全一致，因此这些数值是本轮观测，不是稳定常量。

## 维护者复查步骤

1. 关闭逐点压感，用支持压力大小的笔刷画一条轻→重→轻的直线并规整，确认仍使用平均压感；开启后重复，中段应保留重压
2. 画矩形，在边中间加重后规整，检查压力变化和四个角点都保留
3. 分别从圆的上、右、左侧起笔，顺时针和逆时针绘制，在固定区域加重；规整后压力不应换到另一侧
4. 编辑期间平移、旋转、缩放形状，检查压感跟随形状；非刚性变形按周长对应，需主观复查效果是否符合预期
5. 对非正方形矩形分别选择水平和垂直，确认朝向确实相差 90°；检查 45° 与旋转按钮仍可用
6. 在白底用白色和低不透明度笔刷进入编辑，确认边框与控制点清楚可见；再检查深色背景
7. 完成形状后撤销、重做，保存并回放；另测取消编辑保留原笔迹，以及逐点开关退出重进后的状态

真实手写笔硬件、各笔刷引擎的传感器曲线、复杂纹理、横屏和大字体布局需要对应设备进一步检查。
